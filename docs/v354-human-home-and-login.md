# 好好上課 V3.5.4：以使用者為中心的首頁與登入

## 目標
不重寫原本排課、計費或資料庫：讓老師、家長、學生第一次進網站就知道下一步要做什麼。這版保持 V3.5.3 既有視覺語言，以清楚的稱呼、直接的行動入口替換工程術語與抽象口號。

## 登入文字與流程

- 尚未確認登入狀態：**「正在為你準備好好上課」**／「稍等一下，我們正在整理你的課程和學習紀錄」。只顯示明確載入進度，不誤顯示「尚未登入」。
- 尚未登入：**「歡迎來到好好上課」**／「老師安排課程、家長了解孩子的學習、學生回顧每次進步。從這裡開始就好。」
- 登入動作：**「使用 Google 帳號繼續」**，不要求先提供姓名或選擇工程角色；真正權限仍由既有 Supabase 驗證。
- 第一次使用：老師可以新增學生；家長與學生收到老師邀請後才能看已連結的課程。
- 讀取失敗：**「剛剛沒有成功開啟課程」**與「再試一次」，避免將 Supabase、OAuth 或 API 細節呈現給不熟悉技術的使用者。
- 已登入：**「歡迎回來，課程都準備好了」**，依實際身分顯示首頁。
- 登出後立刻清除私人 DOM 的 V3.5.3 保護維持不變，不等候遠端回覆。

## 家長「今天」

首頁不再沿用老師的空白總覽，改優先回答：

1. **下一堂課**：孩子、科目、日期、時間；若還沒有課程，清楚說明原因並附上查看課表入口。
2. **最近一次學習**：孩子、科目、實際教學內容、專注度與學生心情；沒有回饋時提供合理說明，並可前往完整學習紀錄。
3. **本月費用**：分開顯示「尚待回報付款」「已回報，等老師確認」「老師已確認收到」。全部直接沿用既有 `lessonAllocation` 計算，不以付款狀態自行重新猜測或加入新的計費邏輯。
4. **已連結的孩子**：如果沒有連結學生，明確告知需要接受老師邀請，不顯示假資料。

所有數據都依目前家長已授權連結的學生過濾；不提供更改其他家庭資料的捷徑。

## 老師「今天」

增加三個具體入口：

- **今天的課程**：當日課程數和下一個顯示的學生，直接跳至課程月曆。
- **待補寫的上課紀錄**：本月已完成課程中，上課內容或評分尚未填寫的數量，直接開啟該課程；不修改原收款鎖定。
- **等你確認的收款**：既有待確認的付款批次與付款申請，直接前往收付款介面。

其餘課程、學生、固定課表和付款功能保持原有路徑。

## 不在本次修改的部分

Supabase/Auth/RLS、付款與收款計算、課程資料、付款批次、正式部署規則、邀請與固定課表核心流程。此次只調整前端 HTML、CSS、渲染邏輯及自動測試。

## 回歸與驗收

- 測試登入初始 `getSession()` 尚未回應，畫面不能顯示「尚未登入」；沒有登入時才顯示 Google 按鈕。
- 讀取失敗時有可按的「再試一次」，沒有對使用者展示技術錯誤。
- 測試老師帳號「今天的課程／待補寫／待確認收款」的數據與連結。
- 測試家長下一堂課、最近一次回饋、各付款階段與未連結學生的空狀態；測試不能顯示另一家庭的資料。
- GitHub Actions `node --test tests/*.mjs` 及 V3.5.3 既有隱私、星級、付款與月曆回歸不可退步。
- 真實 Google 帳號登入與角色操作，待 Codex 內建瀏覽器檢查。先用預覽版，不直接合併或更新正式站。
