# 好好上課 V3.3：家長／學生與老師共同排課

## 範圍

- 三方管理同一份原有 `lesson_records`、`recurring_schedules` 與 `schedule_exceptions`，不建立複製課表。
- 老師原有排課、出席、課後評分、付款核對流程保留。
- 家長與學生使用新增的「共同管理課程」面板：新增單堂、每週／雙週課表，修改未完成單堂與未來規則、改期／取消固定課表單堂、停止某日以後或整組固定課表。
- 變更直接生效，沒有「家長提交、老師批准」關卡。其它裝置重新載入頁面可取得最新狀態；本次**沒有加入 Supabase Realtime 即時推播或 Email 通知**。
- 課程金額、鐘點費、教師確認收款及家長付款申報流程維持原有權限；**學生入口不回傳金額**。

## 授權模型

`public.shared_course_action` 是唯一新增的家庭寫入途徑（SECURITY DEFINER，固定 search_path）：
1. 必須使用 Supabase Google 登入取得的 Auth UID。
2. `student_id` 須屬於登入者本人老師、已連結 `student_guardians` 家長，或已連結 `student_links` 學生；三者都逐次在後端重新查詢。
3. `owner_id`、`teacher_id`、`workspace_id`、`hourly_rate` 均由資料庫中的老師／學生紀錄推導，不接受來自瀏覽器的覆寫值。
4. 已完成課程、已收款或進入付款批次、待審核的課程，不允許由家庭共同排課功能改寫；取消保留歷史資料。
5. 維持原始 RLS：家長／學生沒有獲得直接 INSERT/UPDATE 原始課表或付款資料表的授權。
6. 課程操作寫入 `tutor_private.shared_course_events`，授權者可透過 `shared_course_history` 查看最近紀錄。

## 重要限制與操作注意

- 家長、學生只能管理**已接受邀請且仍有效連結**的學生；單純切換網站角色不會增加權限。
- 「修改固定課表」只影響選取的**生效日期之後**。已有完成或付款紀錄的未來課程不可直接修改，需先整理帳務。
- 既有固定課表若有多個星期，共用同一組週期規則。取消未來／停止整組會作用在所有勾選的星期；若要只停週三，應使用單堂取消或把固定課表拆分為不同規則。
- 固定課表虛擬單堂目前能直接**改日期**，不能在單堂層級改科目和時間；修改整組未來課表可以改科目、開始／結束時間。
- 家長與學生新增課程使用老師在學生設定上的預設費率，不開放更改學費。如果該科目實際費率不同，老師需另行核對。
- 預覽模式不會寫入正式資料庫；須使用正式 Google 登入測試。
- 目前的操作稽核專門記錄新共享操作；舊版老師直接使用原排課按鈕產生的歷史記錄不會自動回填到新稽核表。

## 開發、資料庫與驗收

程式：`v2/app.js`、`v2/index.html`、`v2/style.css`；資料庫：
`supabase/migrations/20261021030000_v33_shared_course_management.sql`。

先通過 `node --test tests/*.mjs` 與檢查 DB migration，才可部署正式站。完成後須人工測試：
- 教師、家長、學生三個獨立 Google 帳號登入；先用教師建立學生並寄出／告知邀請連結，另兩個帳號接受邀請。
- 家長新增單堂，學生刷新看到；學生修改時間，老師刷新看到；老師修改後家長再刷新看到。
- 新增每週一三五固定課表；家長取消單堂；學生取消從某日以後／整組規則。
- 其他未連結帳號不能操作、不能讀取課表；撤銷邀請後權限立即失效。
- 已完成及付款中課程的修改／取消必須拒絕；學生頁面不應看到任何收款數字。
- 在手機及桌面上測試各動作，特別是取消的確認步驟與錯誤提示。

**不要**在真實家教與付款歷史上直接做破壞性驗收；應使用明確的測試學生／課程。
