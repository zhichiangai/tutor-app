# V5.3 Team 應收費用基礎：資料模型與安全驗收

**Draft PR #54，基底為 PR #53。正式 Production 不部署、不執行 Migration；測試只允許 localhost 隔離 Supabase 合成資料。**

## 一、功能界線

本階段只建立「已完成 Team 課程的應收費用」，不是訂閱扣款、家長付款、已收款、退款或學費分配。管理者必須輸入該堂課程的每小時約定金額，後端依整分鐘時數計算與確認費用。不得在同一堂課重複確認。

Team 應收金額只存在 `tutor_private.v5_team_lesson_fees`，確認動作同步寫入 `tutor_private.v5_team_billing_audit`。兩個資料表都不開放匿名或已登入的一般客戶端直接讀寫，且啟用 RLS。V4 `lesson_records`、既有收款表與 V5 Team 課程表均不新增付款金額欄位。

## 二、角色與授權

| 情境 | 現任 Team 管理者 | Team 一般老師 | 家長／學生／非成員 |
|---|---|---|---|
| 閱讀 Team 課表（被授權專案） | 是 | 是 | 不在本階段 |
| 閱讀 Team 應收金額、時薪、學費彙總 | 是 | 否 | 否 |
| 確認一堂已完成課程的應收費用 | 是 | 否 | 否 |
| 修改已確認的費用數字 | 否（未來以追加更正實作） | 否 | 否 |
| 修改已確認計價內容的科目／時間／授課者／狀態 | 否 | 否 | 否 |

授權以目前資料庫 `v5_team_governance.manager_user_id` 為準，每次 RPC 重新驗證。管理者轉讓成功後，原管理者即使使用尚未到期的 JWT，也不再能呼叫帳務 RPC。不得因原老師保有 V4 個人 `workspaces.owner_id` 而給予 Team 帳務權限。

## 三、金額定義

- 幣別固定新臺幣（TWD），以整數 cents 儲存，避免浮點數帳務誤差。
- 管理者輸入整數 TWD/小時，後端換算為 cents；允許 0 元補課，限制 0 至 1,000,000 元／小時。
- 課程時間必須是 1 至 1440 分鐘的整分鐘，計算公式為 `round(hourly_rate_cents × duration_seconds ÷ 3600)`，在資料庫進行一次四捨五入。
- 僅能確認狀態 `completed` 且結束時間已過去的課程。確認後固定保存學生、老師、科目、專案、開始與結束時間、時長、時薪和金額。
- `v5_team_billing_overview(team_id,month_first_day)` 以臺北時區的月首至次月月首統計已確認金額，以及當月仍未確認的已完成課程。總額為**應收**，並非已收。

## 四、管理介面

老師角色的「設定」下新增「Team 應收費用（管理者）」；只有目前管理中的 Team 才會顯示。

管理者可以切換 Team、月份，查看已確認的應收總額及每堂課；待確認課程輸入時薪後，確認視窗再次提醒「不是收款且不能直接覆寫」。一般 Team 老師仍使用原跨老師課表，介面不得顯示金額。登出及角色切換會清空前端帳務紀錄。

## 五、隔離測試與尚未實作的範圍

測試需涵蓋一般老師／陌生帳號不可查帳或確認、未完成課程拒絕計價、負數與重複確認拒絕、90 分鐘與 80 分鐘四捨五入、按科目／老師歸屬、確認後課程不可改動計價欄位、私有表不可從公開 API 讀取、管理權轉讓後立即撤權，以及 GUI 實際確認費用且不修改 V4 收款。

此階段**不處理**實收付款、多科目部分分配、同 Team 學生預收款、自動建議抵扣、家長確認或退款。上述功能需獨立資料模型與金額守恆測試，確認帳務補正流程、隔離備份與線上環境後才可考慮正式發布。
