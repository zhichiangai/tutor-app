# V5.3 Team 學生與跨老師課表｜操作及隔離驗收

此文件適用於 Draft PR #53（base=PR #52）；**尚未合併 Main，也未部署 Production**。所有操作驗收只使用本機 localhost 隔離 Supabase 的合成資料。

## 管理者操作

進入老師角色 → 設定 → Team 學生與跨老師課表。目前此區塊不取代 V4 月曆、學生與帳務功能。

1. 選擇 Team，再選擇已有的專案；專案仍由「Team 團隊與專案」建立。
2. 新增 Team 學生：每位學生消耗一次 Team 累計歷史名額，不建立 V4 個人學生。
3. 把同 Team 學生加入此專案：跨 Team 關聯由複合外鍵擋下。
4. 新增 Team 課程：挑選已入學學生、已被分配到專案的老師、科目、開始與結束時間及備註。
5. 月課表顯示所選專案當月的課程及實際授課老師；可以標記完成或取消。
6. 可封存 Team 學生；封存不刪除歷史課程，也不釋放累計名額。

## 一般 Team 老師操作及權限

老師須先加入 Team roster，再經管理者指派到指定專案。僅加入 Team 不授予所有專案學生或課程的讀取權。
可查看已指派專案的學生與課表，替自己建立課程及更新允許的課程狀態；不得新增 Team 學生、跨專案入學關係，或冒充其他老師建立課程。
退出 Team 或取消專案指派後，即使 JWT 尚未到期，也要立即喪失該專案學生及課程讀取權。所有權限最終由資料庫 RLS 決定，前端按鈕不是安全機制。

## 安全與目前限制

- 本模組讀取當月最多 500 筆 Team 課程；大量資料分頁仍待補足。
- 老師名稱目前顯示「我」或使用者 UID 末六碼，正式版需補受控團隊顯示名稱。
- 表單使用安全的 DOM textContent 顯示動態文字，避免以動態 innerHTML 輸出名稱及備註。
- 目前沒有循環排課、跨老師拖曳、付款分配、家長跨專案帳務或預收款。
- 授課老師身分在課程建立後不能由前端更改，歷史歸屬永久保留。
- 不自動搬移 V4 學生、課程或付款；Team 與 V4 個人訂閱名額仍有過渡期相容錨點，正式營運前須拆分完成。

## CI 必測

- 隔離 Chromium 使用本機 GoTrue JWT 及 PostgREST，不連正式 Supabase。
- 管理者 UI：新增學生 → 專案入學 → 建立課程 → 完成狀態 → 登出後清除私人 DOM。
- 跨老師 UI：管理者可安排不同已指派老師的課程；受指派老師可看其專案，但不能查看已退出 Team 的學生或課程。
- V4 課程、帳務及學生完全不變；V3/V4 回歸與 SQL 權限契約均需通過。

未取得真正隔離的 Vercel Preview 與 Supabase 時，不能將 localhost 的 Chromium PASS 視為雲端 GUI 驗收。Codex 後續可於隔離站實測手機 320/375/390/430 px、表單、封存確認和登出隱私；不可動正式 V4 學生或收款資料。
