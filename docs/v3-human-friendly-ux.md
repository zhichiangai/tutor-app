# 好好上課 V3｜課程、帳務、家長管理與角色識別（2026-10-20）

## 新版使用方式

- 頁面頂部常駐顯示「老師模式」或「家長模式」。點一下可切換畫面；角色顯示偏好按登入的 Google Auth User ID 儲存。切換不會授予資料庫權限。
- 老師開啟月曆的未完成課程，點「取消／刪除課程」：
  - 「只取消這一堂」：固定課使用 `schedule_exceptions.teacher_leave`；已存實體課改成不計費的 `leave`。可透過既有還原功能恢復。
  - 「這堂以及未來所有課程」：把選取的固定課表從當天原定日期開始停止；已完成和已付款紀錄保留。
  - 「整組固定課表」：停止整組未來生成；已完成和已付款的歷史不刪除。
  - 「刪除誤建的單堂課」：僅對未完成、尚未進入帳務、且非固定課表的單次課程開放。
- 老師「收付款」上方新增每位學生本月摘要：各科目、已完成堂數、應收、老師已確認、家長回報待確認、未付款；逐堂明細可展開。仍使用原本 payment-ledger.js 計算，包含跨月及部分付款。
- 家長首頁與「學生與家長」頁可查看科目、專注度、學習態度及老師課後文字回饋；未填評分會明確標註。
- 老師可以編輯**尚未接受**邀請的家長 Email，撤銷未接受邀請；已連結家長可「解除連結」。解除是刪除 guardian_invites（依現有 FK ON DELETE CASCADE 原子移除 student_guardians），原邀請不能再次使用；保留學生、課程、付款、歷史評價。
- 所有正式讀寫受 Supabase RLS 保護。家長解除後不再符合學生/課程/課表讀取 RLS；家長自己過去的付款回報仍保留為帳務歷史。

## 安全、相容性與限制

- Migration：`20261020051000_v31_cancel_recurrence_and_invite_edit.sql`。新增 `recurring_schedules.cancelled_from`，新增採用 SECURITY INVOKER 的 `cancel_recurring_schedule(uuid,date)`，對未來實體排課的取消是單次資料庫交易，不會誤刪付款紀錄。移除瀏覽器對 guardian_invites 全欄 UPDATE，只授權修改 `email` 並檢查邀請未被接受。
- 停止整組課表後，已存的未完成未來課程**會從月曆隱藏，但實際資料列仍保留於資料庫**，供稽核；已完成課程仍正常顯示。
- 已完成、已付款、待確認款項的課程不得直接刪除。必須先核對帳務。既有 V2.5 實際計費、V2.7 多租戶 RLS、V3 常用表單記憶全部保留。
- 支援既有兩個前端入口：Vercel 正式網址 `https://tutor.rapid4grad.com/`（透過路由載入 `v2/`），及 GitHub Pages `/tutor-app/v2/`。
- 目前一組固定課表若包含多個平日，「這堂以後／整組」作用於**整組**週期規則；若只要終止星期三但仍保留一、五，應另行拆成多組固定課表。歷史記錄不會自動拆分。

## 測試與發布

- `node --test tests/*.mjs`：全部原有及新增回歸測試，透過 `.github/workflows/v3-regression.yml` 在主分支、PR及開發分支自動執行。
- 驗收重點：兩個獨立老師互不看到學生；家長邀請修改與撤銷；家長解除連結後刷新，無法再讀取學生及課程；教師付款分期金額、跨月費用；週一三五課表取消本堂及停止未來，不改動已確認收款。
