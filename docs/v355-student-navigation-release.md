# V3.5.5 登入導向與學生導覽修正

## 問題原因

- V3.5.4 的 CSS 有 `.student-mode .side-nav,.student-mode .mobile-nav{display:none!important}`，使學生的手機底部選單和桌面側邊選單消失。
- `setView()` 把所有學生非「設定」頁都強制導入單一 `student` 頁，無法讓學生直接切換不同功能。
- 登入初始化會直接設定 `state.view`，但不一定經過 `setView()`，導致所選頁面的可見狀態和導覽 active 不一致。

## 修改

- 老師／家長維持原本五個頁面：今天、月曆、帳務、學生、設定。
- 學生模式新增四個專屬選單：
  - **今天**：本人下一堂課與最近一次學習回饋（僅資料庫授權的 `student_portal_data`，不顯示鐘點費／付款）。
  - **課表**：原有共同管理課程、固定課表及未來課程。
  - **學習**：老師的學生帳號邀請、既有課程、課後內容、專注度與學生心情。
  - **設定**：保留原有帳號、Google 登出與角色切換。
- 在 `render()` 統一執行頁面／導航選取同步；Google 登入成功後直接顯示該角色「今天」，對學生啟用 `student-today`。
- 學生不能由導覽進入帳務、老師學生管理等非授權頁面。
- 老師學生管理中的連結狀態改為「學生已連結／家長已連結」及「等待學生／家長接受」，降低混淆。
- 登出立即清空學生新增的「今天」首頁內容；原 V3.5.4 登出清除保持。
- 本次不修改任何 Supabase schema、RPC、RLS、課程及收款資料。

## 驗收與回歸

- 新增 `tests/v355-student-navigation-role-landing-regression.mjs` 驗證：
  - 學生 4 個選單在桌面和手機皆有。
  - 不同頁面切換時標題與選取狀態同步。
  - 老師／家長 5 個選單不退步。
  - 學生不會進入老師或家長帳務。
  - 學生首頁只顯示自己的課程，且不會顯示費率、金額或其他學生資訊。
  - 登出後私人首頁立即清空。
- 既有 V3.5.4 至 V2 回歸測試全部保留。
- GitHub Actions 結果與正式部署 Commit 需在合併後再次核對。

## 內建瀏覽器真人驗收仍需執行

從本機 `TEST_ACCOUNT_ROLES.md` 對照老師、家長、學生 Google 測試帳號；在 Codex Desktop Built-in Browser 真正操作正式網站，依序確認：
1. 老師登入即顯示「今天」選單及今日待辦；底部或側欄五個選項可操作。
2. 家長登入即顯示孩子的「今天」首頁；仍有原本五個選項。
3. 學生登入即顯示「今天」，可點「課表」「學習」「設定」並返回；底部選單存在，不顯示帳務。
4. 登出後學生的個人課程與回饋無資料殘留；切換 Google 帳號後不顯示上個帳號的私人資訊。
5. 老師「學生管理」的學生、家長帳號狀態、預設時薪及彈窗維持正常。
6. 嚴禁修改正式學生、課程或付款紀錄；解除連結僅查畫面與設定，不拿正式帳號測試。
