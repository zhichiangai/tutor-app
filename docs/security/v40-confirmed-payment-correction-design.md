# 已確認付款批次更正／沖銷：實作設計與驗收門檻

狀態：**設計稿；尚未建立更正 RPC 或改動任何付款狀態。** 本文不是可套用的 Migration。

## 必須同時維持的帳本事實

- 原 `payment_batches`、`payment_batch_items` 永久保留。更正是新的、不可覆寫的紀錄，記下老師、原因、原批次、各課程金額、時間及冪等識別碼。
- 老師只能更正自己已確認的批次；家長可在仍有效連結時查看原紀錄及更正，解除連結後兩者都不可讀。學生角色不可取得金額。
- 每堂原分配額減去所有更正額，必須落在 `0..原分配額`；每批的更正總額不得超過原批次實收。部分更正與多堂課要保留逐堂對照。
- 同一冪等識別碼只可提交一次；相同 key 配不同內容必須拒絕，不得建立第二筆。交易鎖住批次、所涉課程與該學生的付款分配，防止同時新增批次／兩筆沖銷越額。
- 金額計算須用整數分或 `numeric(12,2)`，不以浮點數作權限或餘額判斷。

## 需要一起修改的入口

1. 新增 `payment_batch_corrections` 與逐堂明細表，只准受控 RPC 寫入；RLS SELECT 沿用修正後的批次有效連結判斷，老師保留歷史稽核。
2. `submit_range_payment`、`review_range_payment` 的可用／待確認／已確認計算須扣除更正額；否則沖銷後家長無法重新付款，或舊批次仍被當成全額已收。
3. `tutor_private.guard_paid_lesson` 現在禁止有批次的已收款課程降狀態。需要只在更正 RPC 的同一交易、同一老師、同一課程、稽核紀錄已插入且未消耗時，允許依有效餘額調整狀態；不能開放一般 UPDATE。保留其他已付款課程的時數、費率、日期保護。
4. `v2/payment-ledger.js` 與 `v2/app.js` 的課程餘額、期間收款、每月總額及原批次明細要呈現「原額、更正額、淨額」；家長端在失去連結後不得透過前端快取顯示舊更正資料，登出須清空。
5. 舊式 `reverse_legacy_lesson_receipt` 繼續只處理無批次紀錄，不能把它套用到新批次。

## 本機必過案例

- 兩堂課（各 NT$1,000）的一筆已確認 NT$1,500，先更正一堂 NT$250，再更正另一堂 NT$500；逐堂已收、待確認、未收和老師總額逐次一致。
- 相同冪等 key 重試不會多扣；不同 key 同時更正超額時只有一筆能提交。超過原分配、負數、超過兩位小數、無原因、非老師、別的老師與家長均拒絕。
- 對已更正部分建立新的家長付款、老師確認、再次部分更正；總額不超收、課程保護不被繞過。
- 解除家長連結前可查看自己原紀錄與更正；解除後經舊批次／更正 ID 的 PostgREST 直接查詢皆為空。老師仍能查看全部歷史。
- 使用本機 Auth 簽發 JWT，從空庫重播 Migration，再做 REST/RPC 並行和瀏覽器驗收。不可拿 Node 模擬或正式學生紀錄代替。
