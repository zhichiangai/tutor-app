# 好好上課 V3：多人家教系統與操作體驗（2026-10-20）

## 版本定位與正式入口

- V1：最初的單一使用者流程，`frontend/` 原始碼與資料完全保留。
- V2 / V2.5：原本的家教課程、請假、時數、家長授權與付款功能。
- V2.7：多個獨立老師的 `profiles` / `workspaces` / `workspace_members`，每個工作空間與收付款資料隔離。
- **V3：以 V2.7 為基礎，完成新帳號初始化及加課體驗改善。** 程式資料夾暫時仍命名 `v2/`，這是保留舊部署路徑的相容性安排，不代表網站顯示的是 V2。

在 GitHub Pages 可繼續透過 `/tutor-app/v2/` 測試 V3，新版頁面標題和頁尾則顯示 V3。Repo 根目錄 `index.html` 的 V1 轉址不動。
在 **Vercel** 的 repo-root 部署，`vercel.json` 把根網址和根路徑 CSS/JS/隱私政策重寫到 `v2/` 的 V3 資產，外部網址不需要 `/v2/`。如果 Vercel 專案的 Root Directory 已經是 `v2`，則原本應直接以該資料夾的 `index.html` 作為首頁。本次不修改 Vercel 專案登入授權設定。

## V3 實際改動

1. 桌面月曆工具列加入獨立的月份控制容器，桌面/平板/手機使用不同換行規則，消除標題、上個月/下個月/今天、固定課表、月曆/清單的擠壓。
2. **上次使用的學生、科目、鐘點費、開始/結束時間**：依老師的 Google 帳號及學生個別記錄。下次新增單堂課先套用學生最近成功儲存的資料，科目和金額都有可直接輸入的歷史選項。編輯既有課程時，既有課程資料永遠優先，不被偏好覆蓋。
3. 新增學生時，科目及費率帶入老師常用設定，保留可自行輸入。
4. 由「新增單堂課」可勾選每週一、三、五等多個星期，建立 **1 筆固定課表規則**，而不是一次複製 52 筆 `lesson_records`。每兩週也適用；同一組規則共用相同開始/結束時間。需要不同星期不同時段時，使用既有固定課表管理，分別建立時間不同的規則。
5. 原本只排一堂與每月重複沿用原有課程紀錄邏輯；對每月重複明確說明「未填結束日期預設到下個月」。未付款/已付款的原有課程不被自動重寫。
6. 固定課表也會帶入同一位學生的上次科目、鐘點費與時間。
7. 家長／老師的畫面偏好改為依登入者 ID 儲存，避免同一台電腦切換 Google 帳號時沿用前一個帳號的角色畫面。第一次登入：有家長關聯／邀請且無個人空間者進入家長畫面；其他帳號預設老師。
8. 帳號區顯示工作空間名稱或家長已連結的老師數量；付款期間查詢會記住該帳號上次選擇的學生及日期區間，但不影響費用計算或付款授權。

## 後端偏好資料表

`public.teacher_preferences`：

- `owner_id` 主鍵，關聯 `auth.users.id`
- `settings` JSONB（僅非敏感表單預設值，最大 8 KiB）
- `updated_at`

RLS 只准本人讀寫自己的設定，且 INSERT／UPDATE 僅允許已擁有自己工作空間的老師。**這不是付款紀錄，也不把任何工作空間角色授權放在使用者偏好。**

正式 Supabase 已執行加法式 migration `v3_teacher_preferences`。對應 repo 版檔：
`supabase/migrations/20261020040000_v3_teacher_preferences.sql`。

## 本版明確不做

不加入平台收費、訂閱限制、多人團隊共同編輯或家教費代收。未加入自動寄送家長邀請 Email。

## 回滾

前端可以在 GitHub PR 層級回復 V3 修改並重新部署。老師偏好資料表是新增的，保留該表不影響 V2.7 的運作；**不應刪除既有工作空間、學生、課程或付款資料**。正式回滾資料庫前須先備份并檢查依賴。
